### Why nothing catches it

The gate's own contract, `audit_all.py:24`, is *"review — needs-review count may not grow."* The
code that would enforce it is `audit_all.py:294`:

```python
if "pct" in b.get("review", {}):
    if r["review"]["pct"] > b["review"]["pct"] + 0.5:
        worse("review.pct", ...)
elif r["review"]["n"] > b["review"]["n"]:
    worse("review.n", ...)
```

The baseline has carried `pct` since the day it was written, so the `elif` has never run. And the
stored `review.n` is still **224**, the day-one figure from 2026-07-31 — forty-nine items above the
live backlog — so the branch would not fire even if it were reached. The count is stored and never
checked; the rate is checked and ratcheted.

**Five of the gate's six ratchet paths compare like with like.** `events.explicit_pct` and
`events.target_pct` divide a property of the corpus by the corpus, so both move together;
`forecast.grounded_direct`, `witness_epoch.matched` and `witness_epoch.disagreements` are plain
counts. The sixth divides a **backlog by a flow**. Arrivals pay down the debt, and the only metric
whose subject is unfinished work is the one metric the gate cannot see standing still.

The remedy is one line and it is the parent's. DRIFT already compares six paths against `last_run`
rather than the frozen baseline; `review.n` is not among them. Added there, tonight would have
printed `↓ review.n 174 → 175   ERODED`. **Held, not applied** — standing rule 2, and this project
publishes no fix to the Atlas from an unattended run. The sheet draws no review figure
(`needs_review` reaches no module in `web/js/`), so there is nothing to letter here either.

This is the same class as the window-label defect: a description of the world held constant while
the world's description moves. A rate that replaces a count must keep the count checked.
