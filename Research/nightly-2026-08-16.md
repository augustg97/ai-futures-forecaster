## The defect this run found and fixed

The plate's caption read *"The newest application is ringed in a revision cloud."* The cloud ringed
**the last element of the parent's `entries` array**, which is not the same thing and on three of
the nine mornings in tonight's window was not the same row:

| morning | ringed row's event | newest event in the batch |
|---|---|---|
| 2026-08-12 | 08-10 | 08-12 |
| 2026-08-15 | 08-14 | 08-15 |
| **2026-08-16** | **08-07** | **08-16** |

This morning it ringed a 46-page working paper posted **nine days earlier**, while the one
development that happened today — Nebius and CoreWeave pitching shorter compute contracts in the
week ending August 16 — sat unringed two rows below it.

Two dates run through this plate and they are not the same date: `date`, when the engine applied the
evidence, and `event_date`, when the development happened. Every row on a given morning shares the
first, so within one morning the second is the only date that can order them — and the array is not
ordered by it. The plate lettered neither, so the ring was a claim a reader had no way to test.

**Fixed** in `web/js/app.js` and `web/js/sections.js`:

- the ring goes to the row ranked highest on `(date, event_date)`, which picks the newest
  development within a morning and the newest morning in the fallback view;
- every row letters its own `EVENT 2026-08-07` on the arithmetic line, so the ring is checkable
  against the thing it claims;
- the caption states the rule it follows, and says the plainly useful fact the plate had been
  hiding — that a morning's applications read developments spanning several days.

This is the same family as the defect fixed on 2026-08-15: **a surface that renders its source's
internal representation — a position key, an array index — instead of the meaning, cannot be
checked.** The quiet-morning fallback was exercised by holding `delta.date` past the record: three
rows, ring on the newest application. Audit sweep on the published build: **23 cases · 16,410 marks
· 0 collisions · 0 off-section · 0 overflows · `controlPasses: true`.**
