## The defect this sheet had, and the fix

`axisNotes()` flattened every sub-axis into one line:

```js
secs.push({ h: 'Sub-axes', p: [a.subaxes.map((s) => s.name || s.key).join(' · ')] });
```

`origin` was read by nothing. So on the Coordination note the sheet drew

> **SUB-AXES**
> US-China axis · US domestic preemption vs patchwork · monitoring: Federal AI Policy & Agency…

— a machine-written, uncited, explicitly-unapproved entry set in the same type, on the same
line, as two authored and cited ones. The sheet's own opening note already describes the
mechanism ("the weekly schema review, which may add an axis or a sub-axis on its own and log it
for review"); it just never marked the entries the mechanism produced. Drawing them as authored
is the failure standing rule 2 exists to prevent.

`web/js/app.js` now splits them and prints the parent's `origin` verbatim:

```
SUB-AXES
US-China axis · US domestic preemption vs patchwork

SUB-AXES — PROVISIONAL, NOT APPROVED
C.watch-federal · monitoring: Federal AI Policy & Agency Action residue — added by the
schema review itself, uncited and awaiting the draughtsman's approval. Logged as: auto:
weekly schema review 2026-08-10 — 19 unexplained events in 7 days; FOR AUGUST'S REVIEW
```

No new colour token — the heading uses the existing red every section heading uses, so the
colour code (rule 5) is untouched. Verified at zoom on the live dev server across all three
cases: **T** (authored only) draws one plain heading; **C** (mixed) draws both; **E**
(provisional only) draws only the provisional heading, with no empty authored one.
